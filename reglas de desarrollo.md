# Reglas del desarrollador

- Nunca generar código duplicado.
- Nunca asumir comportamientos sin justificarlos.
- Siempre explicar las decisiones arquitectónicas importantes.
- Preferir soluciones simples antes que complejas.
- Si detectas una mejor arquitectura durante el desarrollo, proponla antes de implementarla.
- Mantener el proyecto preparado para crecer durante los próximos meses sin requerir grandes refactorizaciones.
- Cada módulo debe ser fácilmente testeable y reutilizable.
- Si una implementación puede afectar el rendimiento o el consumo de memoria, explicar el impacto y proponer alternativas.
